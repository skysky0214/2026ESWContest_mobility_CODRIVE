# 실물 카메라로 CARLA 모니터를 촬영하는 거리·경로 보정

2026-10-27 고정 구도에서 보정했다. OX08BC 렌즈 보정 후 1280×720 좌표를 기준으로 모니터 평면과 CARLA 가상 지면을 연결한다. CARLA 객체 좌표는 판단 입력에 전달하지 않는다.

- 9개 ArUco 마커·8개 안정 프레임. 재투영 중앙 오차 0.60px, 최대 1.79px (인식 평가 후 구도 재보정).
- 마커 하나씩 제외한 검증 최대 1.82px, 모서리 흔들림 P95 0.31px.
- `config/camera/physical-screen-ground-20261027.json`: Jetson/Pi 공통 지면 대응.
- `config/camera/physical-screen-driving-corridor.json`: 기존 Tesla bicycle 모델·CAN 조향/차속, 최대 30m·4초. 측정된 이미지 영역 밖 객체·가이드는 사용하지 않는다.

Pi의 실물 입력 `--no-driving-corridor`는 해제하고 위 보정 프로파일로 교체했다. 모델·차량·핸들/페달 임계값은 유지했다. 움직임은 0.4초 이상·4개 이상 표본의 최대 0.75초 회귀로 계산하며, BBOX 하단 지터의 공간 잔차보다 작은 추세를 정지로 취급한다. 자차 움직임은 CAN bicycle 변위로 보상한다.

최초 보정 구도에서 수행한 실제 카메라 경고 시험 기록은 `build/screen-warning-validation-20261027-stable.json`. 정지 기준 구간의 새 경고·충돌 후보는 0개였고, 실제 CARLA 시험 차량 접근에서 TTC 3.0→1.9초와 `속도를 줄이세요` 경고를 확인했다. F1 사전 생성 음성 재생 완료 및 HMI 표시를 확인했다. 경고 문구는 위험 해제 후에도 진행 중인 음성이 끝날 때까지 남을 수 있다.

시험 차량의 CARLA 위치는 검증 참고값만 기록했다. BBOX 하단 접점이 차량의 가장 가까운 표면과 일치한다고 가정하지 않으며, 픽셀 등록 오차가 실제 도로 거리 정확도를 보증하지 않는다. 가상 지면이 평탄하고, 가상 카메라 장착/화각과 물리 카메라·모니터 구도·렌즈 보정/줌이 유지되어야 한다. 구도 변경 시 다시 보정한다.

이전 `physical-validated-20261027` 레이턴시는 지면/경로 보정을 비활성화한 당시 구간 측정이다. 현재 경고 경로의 성능으로 재사용하지 않는다.


## 신호등 보조 모델 전이학습·검증

2026-10-27 실제 카메라의 손실 없는 촬영 243장 중 표식 등록 검증을 통과한 219장을 평가했다. 교차로 11의 유효 89장으로 640×384 상단 영역 두 개씩 생성하고, 거리/장면으로 나눈 학습 108장·검증 70장을 사용했다. 기존 YOLO11n에서 앞쪽 10개 레이어를 고정해 별도의 신호등 단일 클래스 모델을 30 epoch 학습했다. 기존 차량·보행자 모델은 유지한다.

검출 점수만 적용한 후보는 다른 교차로 22에서 정밀도 62%로 거절했다. 세로형 세 램프 중 한 위치가 충분히 밝고 두 위치는 어두운 경우만 발행하는 보수적 버전으로 변경했다. 이후 새 교차로 14의 별도 27장·9개 정차 장면에서 TensorRT FP16 엔진으로 확인한 신호등 TP는 기존 9→17건, FP 0건, 확정 상태 색 오류 0건이었다. 같은 장면의 세 프레임은 서로 독립 표본이 아니며, 먼 신호등은 여전히 다수 미탐한다. 이 수치를 실제 도로 성능으로 해석하지 않는다.

- 고정 구도/세로형 신호등 전용 설정: `config/camera/physical-screen-perception-20261027.json`.
- 가중치·학습/검증/파일 해시: `artifacts/models/vision/signal-recapture-20261027.pt`, 같은 이름의 `.metadata.json`, `.training.csv`.
- 수집·평가·학습·변환 보조 코드: `tools/perception/`.
- 전체 PNG/정답/TP·FP·FN 캡처: `build/perception-eval-20261027/dataset-v2/`, 별도 확인 `confirmation-v3/`.
- Jetson 배포: `deploy/systemd-user/jetson1-signal-refinement.conf` → `99-perception-refinement.conf`. 평가 캡처 훅은 해제했다. 제거하면 기존 `98-ground-input.conf`로 복구한다.

신호색 evidence는 램프 슬롯 밝기 대비이며 확률 보정값이 아니다. 검출 신뢰도 0.4 이상, 대비 evidence 0.65 이상과 기존 3프레임 확인을 모두 사용한다. 세 램프 위치를 판별하기 어려운 신호등·배너는 UNKNOWN으로 제외한다. 카메라 화면의 색이 바래는 문제가 있어 HSV 색상만으로 확정하지 않는다. 현재 HMI/FSM/TTC 및 여성 음성은 변경하지 않았다.

Jetson 서비스 일시 정지 후 동일 프레임을 번갈아 30회 측정한 YOLO+후처리는 평균 0.0502→0.0927초, P95 0.0533→0.1057초였다. 촬영·렌즈 보정·UFLD·DDS·HMI·TTS는 포함하지 않는다. 위 초기 버전은 카메라 약 7~8 FPS에서 Pi 외부 입력 TTL 250ms를 간헐적으로 넘었다. 이를 최종 배포 상태로 두지 않고, 지면 보정이 차선 결과를 덮어쓰는 경로에서 사용되지 않는 중복 Hough 계산을 생략했다. 지면/UFLD 차선 출력과 Pi TTL은 유지한다. 이후 같은 조건의 30회 교대 측정은 기존 YOLO+Hough 평균 0.0583초, 보조 모델 추가+중복 Hough 제거 평균 0.0651초(P95 0.0826초)였다. 카메라 전체 루프는 약 12~13 FPS로 확인했고, 이전 전체 레이턴시 자료를 이 버전의 전체 지연으로 재사용하지 않는다.

추가로 신호등의 공간 박스 후보만 최대 180ms·한 프레임 재사용한다(검출 매 2프레임). 켜진 램프의 위치·밝기 대비는 항상 현재 프레임에서 다시 측정한다. 과거 색/상태는 재사용하지 않는다. 전체 생산 엔진으로 교차로 14의 27장을 10Hz 입력으로 재생하여 TP17·FP0 유지와 색 전환 처리를 확인했다. 거리/보행자/차량 추론은 매 프레임 유지한다.

최종 설정 워밍업 후 Pi HMI API를 10초 동안 2Hz로 확인한 20/20회에서 외부 입력이 유지됐고, 관측된 프레임 나이는 최대 0.217초였다. 이는 짧은 연결 점검이며 장시간 가용성·경고/TTS 지연 시험을 대신하지 않는다. 처음 후보의 간헐적 입력 유효시간 초과 기록과 최종 결과는 각각 `runtime-availability.json`, `runtime-availability-final.json`으로 분리했다.
