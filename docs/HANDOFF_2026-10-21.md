## DMS/HMI behavior alignment

The integration cabin policy accepts awake, distracted, drowsy, head_drop and phone;
smoking/yawn are ignored. Phone confidence remains 0.65. Accepted behavior and its
confidence travel as optional DriverState fields. Deploy the Pi consumer before
the cabin publisher because older decoders reject unknown fields.

The main HMI maps these classes to 정상 / 주의 분산 / 졸음 감지 / 고개 떨굼 감지 /
휴대폰 사용 감지. Explicit null means no accepted behavior and shows 상태 수신 대기;
missing/expired packets are identified separately. Awake is normal even while
old INFO commands or smoothed drowsiness remain. Real WARNING/CRITICAL rules
retain priority; XGBoost stays a separate display-only indicator. Observation
speech confirmation/rearm protection remains enabled. Native diagnostic footer
shows the exact canonical behavior sent to Pi.

## HMI clean video (supersedes diagnostic stream)

Removed the HMI stream overlay option. Cabin MJPEG always receives clean frames;
local Jetson `--preview` remains optional and is disabled in the default service.
The temporary 70-dms-debug.conf activation is removed during deployment.
Behavior recognition, thresholds and HMI state labels remain unchanged.
