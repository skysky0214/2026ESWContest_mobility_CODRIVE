# 반복 주행 시나리오

수정 기준 워크스페이스: `ESW2026-latest`. 기존 Town10HD_Opt의 hero와 전방 RGB 카메라를 사용한다. 자차 운전은 G29 수동이며, CARLA 객체 좌표는 기록에만 사용하고 센서 인식 결과로 전달하지 않는다.

실행: `scripts/run-carla-scenario.sh --config config/carla/scenarios/rain-night-slow-vehicle.json`

제어 페이지: <http://127.0.0.1:18081/>. latest의 `tools/carla_front_screen.py` 화면에서도 숫자키로 선택할 수 있다.

| 키 | 장면 | 동작 |
|---|---|---|
| 1 | 보행자 + 좌측 차선 이탈 | 기존 반복 장면 |
| 2 | 후방 왼쪽 긴급차량 + 황색 신호 | 정지선 전방 약 65m에서 출발. 정지선까지 앞범퍼 거리 30m 이내·5km/h 이상·차선 중심 ±1.75m에서 황색 3초 후 적색. 뒤 왼쪽 구급차 접근과 휴대폰 재생 안내 시작 |
| 3 | 우천·야간 + 전방 저속 차량 | 25m 앞 선행차, 자차 5km/h 이상 출발 시 목표 10km/h로 주행. CARLA 우천·야간 화면 + 명시적 시연 환경값 |
| 4 | 페달 급가속 | 기존 장면, 기준 엑셀 90%·가속도 4m/s² |
| R | 현재 장면 재시작 | 정차 및 엑셀 해제 필요 |

장면 선택과 R은 자차 속도 0.5m/s 미만, 엑셀 3% 이하일 때만 허용한다. 다른 차로로 나가거나 교차로를 지나친 뒤에는 정차하고 초기화한다.

②는 휴대폰을 후방 왼쪽에서 재생한다. 두 마이크는 좌우만 판별하며 후방은 배치 가정이다. 구급차는 후방 접근 후 자차 뒤에서 제동한다. 경고용 사이렌 감지는 실제 음향 인식 경로만 사용한다. 화면의 안내 표시는 RGB 토픽/Jetson 입력에 섞이지 않는다.

③은 강수 80%, 노면 젖음 100%, 태양 고도 -20°로 설정한다. 판단 입력은 비·야간 고정값(가중치 1.38)이며 실제 기상 API 결과라고 표시하지 않는다. HMI에는 ‘시연 날씨’로 표시한다.

`scenario_context` DDS(domain 42) heartbeat 5Hz로 선택한 시연 설정만 전달한다. Pi는 지정 출처 `laptop.carla.scenario`만 허용한다. 2초간 수신이 없거나 장면 해제 시 실제 API와 기본 음향 경고 설정으로 복귀한다. 음향 경고는 ② 동안만 추가 활성화한다. 기존 TTC/FSM 및 실제 CAN 수신은 유지한다.

시나리오 소유 NPC만 제거하며, 전환/종료 시 날씨·자차 조명·신호등 상태/동결 설정을 복구한다. 매 시험의 설정, CARLA 참고값, Pi 결과는 `build/carla-saved-scenarios/trial-*`에 기록한다. 참고값이나 장면 발동 성공은 Pi의 실제 인식/판단 성공을 의미하지 않는다. 주행·마이크 시험은 별도 확인해야 한다.

## 제어 프로세스 분리

`run-carla-scenario.sh`는 G29를 독립 사용자 서비스 `codrive-carla-g29`로 시작하고 시나리오는 `--no-g29`로 실행한다. 시나리오 종료·교체·오류가 핸들/페달을 종료하지 않는다. `--no-g29`를 직접 지정하면 기존 G29를 사용하며 새로 시작하지 않는다.

NPC 소실은 actor handle의 `is_alive`뿐 아니라 현재 월드 스냅샷의 actor ID로 확인한다. 소실 시 실행기는 `target_missing` 상태로 유지하고, 운전 중 임의 재생성/이동 없이 정차 후 R 초기화를 기다린다. 보드 DDS의 유선 설정은 ROS/G29 자식 프로세스에 전달하지 않는다.
